# 飲食篩選與自訂出發點

## 葷／素

新增店家時標記以下其中一種：

| 儲存值 | 顯示 | 可通過的篩選 |
|---|---|---|
| unknown | 葷素未確認 | 不限制 |
| meat | 葷食 | 不限制、葷食 |
| vegetarian | 素食 | 不限制、素食 |
| both | 葷素皆有 | 不限制、葷食、素食 |

素食是人工確認「有素食餐點」，不代表自動驗證全素、蛋奶素、五辛素或共鍋；介面會提醒有特定需求時向店家確認。舊資料沒有標記時保留 unknown，不推測餐廳分類等於葷素類型。

篩選採 AND：距離、天氣、飲食、料理、預算等條件都符合才上轉盤。不符合的原因仍顯示在排除清單。

## 出發點

頁面上方的「更換出發點」在私人與共用模式都能用，與新增店家共用互動地圖：

1. 填出發點名稱與經緯度，或按「使用目前位置」。定位只在主動按下後詢問瀏覽器權限，失敗可改填座標。
2. 按「在地圖選位置」後，地圖切換成選出發點模式。點空白位置或既有店家標記會帶入座標，再確認儲存；這個模式不新增店家。
3. 更換後更新距離、天氣查詢位置、地圖出發點與 Google Maps 步行導航起點。
4. 設定存在此瀏覽器的 `lunch-club-origin-v1`；私人與共用入口共用此個人設定，不改變其他使用者的出發點。
5. 「恢復預設出發點」移除個人覆寫。預設為板橋車站北二門附近的待校正位置；共用模式可由擁有者透過 ORIGIN_LAT／ORIGIN_LNG／ORIGIN_NAME 設定預設值。

出發點可隨時換，不必新增一間店；新增店家的表單會清楚顯示目前出發點，供填寫避雨標記。直接開本機 HTML 時沒有互動底圖，可填座標；定位與 Apps Script iframe 權限需實機驗收。

## 避雨標記為什麼也要記出發點

「從板橋車站到店家有遮蔽」不代表「從家裡到店家有遮蔽」。因此每間店的避雨資訊另存 `covered_origin`：

```json
{"lat":25.0143,"lng":121.4638}
```

雨天條件需要 covered_route = yes，而且目前出發點在該筆路線出發點 10 公尺內；否則顯示「此出發點的避雨路線待確認」。這是人工路線標記的位置比對，不是自動步行路線分析。

舊店家沒有來源座標時不會假設新起點可以避雨。管理者可在試算表確認後補填路線出發點；目前一間店只維護一組共用避雨路線，不提供每位訪客編輯共用資料。

## 舊試算表升級

RestaurantsFree 在既有 12 欄後面新增：

- `diet`
- `covered_origin`

程式只對完全符合 v4 表頭的資料補上新表頭，不改舊列、店家 ID 或評論／投票關聯。舊列讀取時預設 diet = unknown、covered_origin = null。若表頭被改成其他格式會報錯，不覆蓋。

新店家由表單將葷素與避雨出發點寫入；若未確認避雨則不寫路線出發點。管理密語與共用新增權限維持後端驗證。
