# 管理者：店家資料要怎麼補？

## 「83 間有資料待補」代表什麼？

不是 83 間都不能抽選。舊提示把基本資料與選填資訊合在一起計算，新版改成分別顯示：

- **基本資料待確認**：店家編號、店名或位置有問題，該店暫不抽選、留言。
- **選填資訊尚未確認**：例如預算或營業時間沒填；不限制相關條件時，仍能抽選。
- **一般資訊**：電話、地址等；缺少電話不會讓店家退出轉盤。

在「店家與食評」或挑店家頁面，按 **查看缺少哪些資料與補充方式**，可看每個項目缺幾間。點單一店家可看那家店的缺漏。這些數字會隨重新讀取試算表而更新。

## 先補這三項

1. 開啟你原本部署時使用的 Google 試算表。
2. 切到 **RestaurantsFree** 分頁，依店名找到對應店家。
3. 優先補 **G 欄 category（類型）、M 欄 diet（葷素）、H 欄 budget_twd（每人預算）**。
4. 回網站，進「店家與食評」按 **重新整理店家**，確認分類與提示已更新。不必重新部署網站。

只修改確認過的儲存格，保留英文表頭、欄位順序與原本的 `id`。不要整份重新匯入，不要改 `Reviews`、`ReviewVotes`、`Members`，既有評論會繼續連到原店家。

| 要補的資訊 | 欄位 | 可填的內容 | 不知道時 |
|---|---|---|---|
| 店家類型 | G：`category` | 正餐、早餐店、便當／快餐、小吃、麵食、拉麵、牛排、火鍋、咖哩、義大利麵、咖啡廳、甜點、冰品；原本台式、日式、韓式、西式、輕食也支援 | 留白。若有原始清單分類，網站會先沿用；否則顯示尚未分類 |
| 葷素 | M：`diet` | `meat`＝葷食、`vegetarian`＝素食、`both`＝葷素皆有、`unknown`＝未確認 | `unknown` 或留白，不猜測 |
| 每人預算 | H：`budget_twd` | 例如 `150`，只填 1～10000 的整數；以實際用餐估計，整份名單採相同判準 | 留白；不要填 0、150元、100～200 |
| 電話 | F：`phone` | 例如 `02-1234-5678`；先將儲存格格式設成「純文字」，避免開頭 0 消失 | 留白 |
| 地址 | C：`address` | 已確認的完整地址 | 留白，已有有效位置仍可抽選 |
| 營業時間 | J：`weekly_hours` | 依下方七天格式填寫 | 留白＝七天均未確認，不等於公休 |
| 全程避雨 | I：`covered_route` | `yes`＝已確認全程避雨；`no`＝需走露天路段；`unknown`＝未確認 | `unknown` 或留白 |
| 避雨的出發點 | N：`covered_origin` | 只有確認避雨時，填入確認該路線的出發點，格式見下方 | 留白；即使填 yes，沒有可核對的起點仍不通過雨天篩選 |

素食請填 `diet`，不必犧牲餐點類型。例如素食拉麵可填 `category=拉麵`、`diet=vegetarian`。全素、蛋奶素、五辛與共鍋需要再向店家確認。

原清單只有「正餐」不代表已確認是台式或拉麵。確認後直接改 `RestaurantsFree.category` 即可，新分類會優先於「原始清單」分頁。未知分類不會靠店名自動猜測。

## 營業時間：先確認，再填七天

`weekly_hours` 一個儲存格存七天，順序固定為 **星期日、一、二、三、四、五、六**。

- 未確認：`{"status":"unknown","spans":[]}`
- 已確認休息：`{"status":"closed","spans":[]}`
- 確認有營業：`{"status":"open","spans":[{"from":"11:00","to":"14:00"}]}`
- 每天最多兩段，例如午餐與晚餐；時間為 24 小時制。關門時間早於開門代表隔天關門，不支援同時刻表示 24 小時。

以下**只是格式範例**：週日休息、週一至週五 11:00–14:00、週六未確認。只在實際符合的店家使用，不能整欄套用所有店家。複製整個陣列到該店的 J 欄一個儲存格：

```json
[{"status":"closed","spans":[]},{"status":"open","spans":[{"from":"11:00","to":"14:00"}]},{"status":"open","spans":[{"from":"11:00","to":"14:00"}]},{"status":"open","spans":[{"from":"11:00","to":"14:00"}]},{"status":"open","spans":[{"from":"11:00","to":"14:00"}]},{"status":"open","spans":[{"from":"11:00","to":"14:00"}]},{"status":"unknown","spans":[]}]
```

這是例行時段，不會自動知道臨時公休、連假或店家即時變動。電話與營業時間請以店家確認內容維護。

## 避雨資訊

確認的是「從哪個出發點走到店家」，不是店家本身有沒有屋頂。填 `yes` 時，N 欄需要相同出發點，例如格式：

```json
{"lat":25.0143,"lng":121.4638}
```

數字僅示範格式，請換成你實際確認的出發點；這個範例不代表已校正的板橋車站北二門。每位使用者換起點後，不會自動沿用未確認的避雨路線。不確定就保留 `unknown`。

## 不用一次補齊

先補常去店家的類型、葷素、預算，就能讓常用篩選有意義。其餘慢慢補；「不限／不拘」會保留基本資料完整的店。選定特定條件後，資料不足的店會暫時排除，網站不會自動替你放寬條件。
