# 資料缺漏與防呆

提醒已區分基本資料、影響篩選的選填資訊，以及電話等一般資訊。「選填資訊尚未確認」不表示店家不能抽選。v6.4 支援多餐點類別；舊正餐等大類待細分，部分分類打錯時保留可辨認的類別並提示。每項待補數量可從網站的「查看缺少哪些資料與補充方式」查看。實際填寫步驟與例子見 [管理者補資料指南](fill-restaurant-data.md)。

這版將「讀取既有資料」與「新增資料檢查」分開。讀取時逐筆整理，缺漏或錯誤會標示待補，不會替店家猜電話、價錢、葷素或營業狀況；新增時仍拒絕格式錯誤的已填內容。表頭或試算表權限錯誤仍會明確停止，不當成空名單。

## 店家欄位

| 欄位 | 空白、缺值或格式錯誤時 | 操作與篩選 |
|---|---|---|
| 店家編號 | 缺漏、不符格式或重複，保留於畫面並標示待確認；畫面暫用編號不寫回試算表 | 暫不抽選、不留言；重複編號的所有相關店都暫停 |
| 店名 | 顯示「店名待補」 | 暫不抽選 |
| 緯度／經度 | 位置未知，空白不轉成 0；超界、布林值與不合法文字不當座標 | 暫不抽選、不放地圖標記、不產生導航目的地 |
| 地址 | 顯示「地址未提供」 | 已有正確座標仍可抽選 |
| 電話 | 顯示待確認，不建立無效撥號連結 | 不影響抽選，不編造電話 |
| 餐點類別 | 顯示「尚未分類」；有可核對的原始分類時做同義名稱對應。多個類別可辨認的部分保留，錯誤部分提醒待確認 | 未分類包含在「不限／尚未分類」；每家店可符合多個餐點，但不重複計入轉盤 |
| 葷素 | 葷素待確認 | 指定葷／素條件時不通過 |
| 預算 | 未標記，不能把空白、布林值或非法金額當作 0 元 | 「不拘」可抽；選金額上限時不通過 |
| 全程避雨 | 未確認 | 雨天條件不通過 |
| 避雨出發點 | 位置未確認；不把空白當座標 | 即使避雨填「是」，缺起點仍不通過雨天條件 |
| 每週營業時間 | 空白或無法解析時，七天均未知；單日格式錯誤只將該日標為未知 | 啟用營業條件時未知不通過；未知不顯示成休息 |
| Google Maps 連結 | 無效連結不使用 | 有正確位置時仍可產生網站自己的 Google Maps 連結 |
| 建立時間 | 留空 | 不影響抽選，不編造日期 |

主畫面顯示資料待補與暫不可抽選的店家數。點店家可查看缺漏項目。其他資料完整的店仍可抽選；篩選後不足兩間時不能抽，不會自行放寬條件。

## 評論、投票與會員

- 評論的店家編號、評論編號、品項、回饋或分數不合法時，該則暫不顯示、不計平均，其他有效評論仍能載入。真正的 **0 分**仍是有效分數，空白不是 0 分。
- 重複評論編號的評論暫不顯示，避免投票連到不確定的內容。評論時間不明時顯示「時間未提供」。
- 無效投票不計票。重複的「同帳號＋同評論」只採最後一筆有效狀態，避免重複加票。表內原列保留，畫面會提示有部分資料未計入。
- 沒有舊作者資料的評論維持「以前的匿名食友」。會員暱稱不合法時回到未填暱稱狀態；新評論帳號仍由 Google 驗證，完整信箱不公開。
- 登入、管理密語與授權失敗仍會拒絕寫入，不會因為容錯而放寬權限。

## 儲存與外部資料

- 試算表讀取不改寫原列。必要的舊版表頭擴充仍依既有部署規則進行。
- 私人名單顯示時保留原始店家內容，勾選與抽選不會把整理後的缺值覆蓋回原店家資料。
- 私人名單整段儲存內容無法解析時，顯示錯誤並保留原內容，仍可切換到共用名單。不以空名單覆蓋它。
- 無效出發點回到可確認的預設位置；天氣或地圖讀取失敗仍顯示提示，不能將未知天氣當作晴天。用餐區間每個所需小時都要有唯一且介於 0～100 的降雨機率，缺漏、重複或非法數值一律視為未知。
- 名單格式整體錯誤、讀取失敗或逾時可重試；遲到回應不覆蓋已取消的操作。

## 驗證與範圍

`npm test` 執行七組可攜測試。`tests/data-quality.test.cjs` 包含 126 組逐欄異常輸入，另驗證篩選、營業時間、座標、危險連結、重複編號、試算表原列保留、零分完整性與投票去重。`tests/workflow.test.cjs` 驗證類型銜接與缺漏分類統計；`tests/food-types.test.cjs` 驗證多餐點、去重、舊分類、混合錯誤、既有欄位儲存與評論關聯。瀏覽器以本機服務替身測試流程、獨立食評與登入操作；Google 正式部署與 iPhone Safari 仍需更新後確認。這是已列舉案例的驗證，不是保證任何格式或未來外部服務變動都不會出錯。
