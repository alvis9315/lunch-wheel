# 午餐俱樂部：目前狀態與後續工作

更新日期：2026-09-24 · 版本：6.11.0

此文件記錄目前程式與交付狀態；不代表線上網站已更新。正式部署仍由擁有者在私人 Apps Script 專案操作。

## 這次完成什麼

- 第一頁餐點類別可複選，點卡片只切換勾選；按「下一步，挑店家」才進第二頁。
- 「不限」包含全部類別，與個別類別互斥。最後一個個別類別取消後，恢復不限。
- 早餐店＋牛肉麵會列出任一類別符合的店；同一家店符合兩類也只列一次。
- 返回更換類別時保留篩選條件及仍屬於新類別的勾選店家；需重新確認後才進轉盤。
- 取消抽選 20 間上限，至少要有 2 間符合條件的店。「全選目前顯示」會選目前搜尋、分類與篩選後的全部店家。
- 20 間以內轉盤顯示店名；超過 20 間改編號，超過 40 間只顯示部分編號以免重疊。展開「本次抽選名單」可對照所有編號與完整店名。
- 所有符合條件且已確認的店均參加，等機率抽選；畫面省略部分編號不會省略候選店家。保留約 2.5 秒旋轉動畫，系統偏好減少動態時縮短動畫。
- 本次不新增或更改試算表欄位、不重匯店家、不更動登入設定。

## 如何更新目前 Apps Script

1. 下載並解壓縮儲存庫根目錄的 `Lunch-Club-Apps-Script.zip`。
2. 到原本的 Apps Script 專案，完整替換 **Code.gs**（原本叫 code.gs 也可以）與 **Index.html**。使用 ZIP 根目錄的兩個檔案；不要把 src 下的單一檔案貼上。
3. 本次 `appsscript.json` 沒變；已有正常部署可保留。指令碼屬性中的試算表 ID、管理密語、Google 登入設定全部保留。
4. 儲存 →「部署」→「管理部署作業」→ 編輯原本的網頁應用程式 → 版本選「新版本」→ 部署。維持執行身分「我」、存取權「任何人」。
5. 開啟原本 `/exec` 網址並重新整理；使用說明應顯示 **6.11.0**。編輯原部署可保留網址，通常不必改 OAuth 重新導向網址。
6. 試選兩種類別，確認第一頁不自動跳頁；按下一步。全選超過 20 間後確認、抽選，檢查完整名單與結果。

不要另建部署來代替版本更新，否則網址可能不同，Google 登入重新導向設定也要跟著檢查。`/dev` 是開發測試網址，正式分享仍用 `/exec`。

## 已有功能

| 區域 | 目前作法 |
|---|---|
| 使用流程 | 現有名單：多選餐點 → 左側篩選／右側店家 → 確認 → 獨立轉盤 |
| 店家分類 | 共用固定 27 類；試算表 category 決定每店分類，可用頓號填多類。新增類別要更新共用分類設定再建置 |
| 排版與配色 | 桌機類別 4／8 欄切換；窄螢幕自動調整；依七個餐點群固定配色，多群用分色與文字標籤 |
| 篩選 | 直線距離、天氣／避雨、葷素、預算、用餐時段營業、跳過上次店家；未知資料不冒充符合指定條件 |
| 店家名單 | 獨立入口，完整店家資訊及評論頁，不必先走抽選流程 |
| 帳號 | 公開瀏覽與抽選，Google 登入後評論、投票、推薦店家；匿名／暱稱在帳號設定一次，新評論沿用 |
| 評論 | 品項、回饋、-100～200 分；滑桿／輸入分數同步形容詞。送出前確認，只新增；歷史作者名稱保留 |
| 投票 | 同帳號對同評論讚／爛互斥，可改票與取消，後端驗證登入 |
| 推薦店家 | 頁底開表單，至少店名及 Google Maps 連結；存投稿等待團長處理，不直接加入轉盤 |
| 隱私 | 一般食友只見匿名或自訂暱稱；Google 帳號不公開。團長通過後端驗證才能看作者帳號 |
| 地圖／天氣 | Leaflet＋OpenStreetMap、Open-Meteo；Google Maps 只提供外部連結，未串付費 Places API |
| 本機測試 | `npm run dev` 或 `start-local.cmd`；虛構店家、模擬 Google 帳號與記憶體試算表，不寫線上 Google Sheets |

## 程式與資料放在哪裡

前端為 HTML／CSS／JavaScript，透過 `google.script.run` 呼叫 Apps Script。後端處理登入驗證、讀取與寫入私人 Google 試算表。

- `src/`：共用前端、篩選、分類及評分規則。
- `apps-script/`：後端與 Apps Script 設定。
- `scripts/build.mjs`：合併成 `dist/Index.html`、`dist/Code.gs`、`dist/appsscript.json`。
- `scripts/local-*`：只供本機測試的服務與模擬資料，不包含於正式頁面。
- `tests/`：可攜的邏輯及後端測試；執行 `npm test`。
- `docs/`：部署、欄位填寫、登入、隱私與功能說明。

| 試算表分頁 | 用途 |
|---|---|
| RestaurantsFree | 店家名單、位置、分類、葷素、預算、營業及避雨資料 |
| Reviews | 店家評論、分數、作者身分與留言時的公開名稱快照 |
| ReviewVotes | 帳號對評論的投票 |
| Members | Google 身分與會員顯示名稱設定 |
| Suggestions | 使用者投稿及團長處理狀態 |
| 原始清單（若存在） | 舊匯入資料來源；依店家 ID 銜接，不覆蓋 RestaurantsFree 已填分類 |

保持試算表限制共用，不要為了公開網站而公開這份表。密鑰、管理密語及私人帳號設定留在 Apps Script 指令碼屬性，不放 GitHub 或前端。

## 後續方向：Sites 前端＋保留現有試算表

**使用者已選定此方向，本次尚未實作遷移，也未部署 Sites。** 目前 Apps Script 版本先繼續使用。

目標：同一套前端程式支援 Apps Script 與 Sites，保留現有店家、評論和投票資料，避免分成兩套畫面各自修正。

待完成：

1. 確認實際 Sites 專案、可用後端執行環境、部署方式與帳戶方案限制；不能先保證永久免費或無限用量。
2. 抽出資料呼叫層：Apps Script 仍用 `google.script.run`；Sites 改用受保護的 HTTP 介面。
3. 設計 Sites 與 Google Sheets 間的伺服器連線、Google 登入回呼與登入狀態傳遞。不能把 Apps Script 密語／OAuth secret 放前端，也不能用匿名公開寫入端點代替驗證。
4. 確認跨網站請求、Cookie／憑證、錯誤重試、重複送出與限流行為；完成讀寫整合驗證。
5. 增加 Sites 建置與部署說明，保留 Apps Script 建置目標；測試通過再切換正式入口。

可另評估 clasp 同步現有 Apps Script，減少手動貼檔，但目前未配置自動部署。

## 還沒做／已知限制

- 「自己建立」入口仍關閉。想要的「搜尋店家 → 點選／拖曳加入」尚未完成，不能要求一般使用者手填經緯度作為最終流程。
- 店家電話、價格、營業時間等仍需團長維護，不會自動從 Google Maps 取得。臨時公休與節日營業不能由目前資料保證。
- 資料待補提醒目前尚未全面限制只讓團長看到，列為後續介面待辦。
- 評論編輯／刪除、團長隱藏不當留言與封鎖帳號未做。已有後端驗證與基本頻率限制，未做進一步反灌水管理介面。
- 真正 Google OAuth、私人試算表權限及正式寫入需部署後整合驗收；本機模擬通過不代表 Google 實際授權已驗證。
- iPhone 實機 Safari 尚需驗收；Chrome 手機寬度測試不能取代實機測試。
- 不設產品層級店數上限，但瀏覽器仍受資料量與效能限制；未承諾上萬家店的渲染效能。
