# v6.6：推薦店家、依試算表顯示分類

## 入口分類現在從哪裡來？

**以前**：v6.4／v6.5 的分類名稱由程式預先列出，試算表只提供店家與數量；不在清單內的名稱可能被當成未分類。

**現在**：入口與「店家與食評」都從每家店的分類欄位整理出選項，只顯示有店家的分類。「不限」第一個；同一家店符合多類別，仍只算一家、在轉盤中只出現一次。

你提供的分類都能直接使用，名稱不合併：

速食、咖哩、拉麵、早餐店、早午餐、牛肉麵、牛排、小吃店、快餐便當、咖啡廳、輕食咖啡廳、韓式料理、鍋物、烏龍麵、素食、冰店、甜點、粥店、港式、**台式**。

程式保留這份清單作為常用排列、圖示與團長新增店家時的勾選捷徑；它不是分類限制。日後填入新的分類，例如「壽司」，有店家使用並重新整理後就會出現，不需要再改程式或部署。未指定圖示的分類使用餐盤圖示。

### 試算表怎麼填

1. 改線上 Google 試算表 **RestaurantsFree → G 欄 `category`**，一列對應一間店。
2. 單一類別填 `台式`；多類別在同一格以頓號分隔，例如 `早午餐、輕食咖啡廳`。
3. 到網站「店家與食評 → 重新整理店家」，再回「抽午餐」查看。

讀的是**每家店儲存格裡的內容，不是試算表下拉選單的選項設定**。只新增下拉選項，尚未套用到任何店家的分類不會出現。沒有讀取或更改你的線上私人試算表；請在部署後依實際店家數核對。

G 欄已填寫的分類優先。G 欄空白、`其他` 或 `unknown` 時，才沿用「原始清單」以店家 ID 對應的「店家類型」。若你只修改「原始清單」，而 G 欄已有其他明確分類，請同步確認 G 欄。

- 早餐店與早午餐分開；咖啡廳、輕食咖啡廳、甜點分開，不擅自合併。
- 名稱前後空白會去除。頓號、逗號、分號、換行可分隔多類；斜線是名稱的一部分。
- 每個名稱最多 32 個字，允許中英文、數字與常用分隔符號；不接受 HTML、網址等不適合作為分類的內容。無法使用的部分會提示待確認，不影響其他有效類別。
- `正餐`、`其他`、`unknown`、空白仍是尚未分類，可從「不限」選店。這次不再把「台式」等國別類別排除。
- 新分類的錯字也可能成為新選項，請統一用字；不會根據店名猜測或重寫原表。
- G 欄 `素食` 是店家類別，M 欄 `diet` 是葷素篩選依據。確認是素食店時可同時填 G＝`素食`、M＝`vegetarian`；沒有確認前不要自行補造。

## 食友怎麼投稿？

「選餐點」、「挑店家」與「店家與食評」都有 **找不到你喜歡的店家？ → 我要推薦店家**。

- 必填：店名、Google Maps 分享連結。
- 選填：推薦理由，最多 1000 字。
- 不用填經緯度、電話或營業時間。
- 可先填表，送出前才要求 Google 登入；登入後內容保留，要再按一次送出。不會自動投稿。
- 只接受 Google Maps 連結，不抓取或解析 Google 店家資料；不使用付費 API。
- 投稿不會直接加入候選名單或轉盤，須由團長確認。投稿內容及帳號只供團長查看。
- 同次送出重試不重複新增；相同店名與連結已有待確認投稿時會提醒。每個帳號 10 分鐘最多 3 間、滾動 24 小時最多 10 間。

## 團長怎麼處理？

1. 網站按 **團長登入**，輸入原本通關密語。
2. 按 **查看店家投稿**。可看店名、推薦理由、Google Maps 連結與投稿帳號。
3. 確認店家後，使用原本新增店家的方式加入名單；店家位置與營業資訊仍由團長確認。
4. 完成確認或決定不加入後，可按 **標記已處理** 收起投稿。

「標記已處理」不會自動新增店家，也不刪除投稿。這可避免未確認的推薦直接進入抽選。查看與處理每次都驗證團長權限；Google 一般會員不能讀取投稿清單。關閉視窗或團長登出後清除私人投稿內容，遲到的回應不顯示。

### 新增 Suggestions 分頁

第一次投稿或團長開啟投稿清單時，程式會自動建立 **Suggestions**：

`id | request_id | name | maps_url | note | submitter_key | submitter_email | created_at | status | reviewed_at`

- `status`：`pending` 待確認、`done` 已處理。
- `submitter_email`：由 Google 登入取得，不信任使用者自行提供的帳號。
- 原本店家、評論、會員及投票分頁不需要重新匯入或改表頭。
- 試算表仍保持限制共用。

## 用字調整

已檢查入口、挑店家、店家與食評、轉盤結果、帳號、團長登入、出發點、資訊提醒及新增店家表單：

| 舊說法 | 新說法／操作 |
|---|---|
| 管理員／名單管理者 | 團長 |
| 預算未標記／葷素未標記 | 預算還沒確認／葷素還沒確認 |
| 基本資料待確認，暫不開放抽選與評論 | 店名或位置還沒確認，暫時不能抽選或留言 |
| 一般使用者看到試算表表頭、編號與匯入說明 | 改成請團長確認及重新整理店家的操作提示 |
| 直接要求填寫出發點經緯度 | 先用定位／地圖選點；手填位置收進可展開的進階選項 |
| HTTPS Google Maps 格式錯誤 | 引導到店家頁按「分享」再複製連結 |

管理者維護資料必須知道的欄位名稱保留在文件，沒有混進一般選店流程。出發點進階欄位及團長新增店家的位置欄位仍保留緯度／經度的正確名稱。

## 更新與驗收

1. 下載新版 ZIP，完整替換 **Code.gs、Index.html**。
2. 原部署「編輯 → 新版本 → 部署」。執行身分保持「我」、存取保持「任何人」；Google 登入與管理密語不用重設。
3. 「使用說明」確認版本 **6.6.0**。
4. 核對實際分類及台式店家數，再測試投稿與團長處理。

本機測試包含動態分類、權限、輸入檢查、重試去重、投稿頻率、投稿分頁、原店家名單不被修改、匿名食評回歸及手機尺寸。Google／試算表連線以測試替身驗證；正式部署與 iPhone Safari 仍需上線後實際確認。
