# v6.7：統一分類、推薦店家

## v6.7：統一固定分類主清單

這版統一採用附圖的 **27 類**，名稱、順序、圖示都集中在 `src/catalog.js` 的 `categoryDefinitions`。入口、食評類別、團長新增店家的選項與存檔檢查共用此設定。建置時同一份檔案會放入 **Code.gs 與 Index.html**，兩份都要更新，不能只更新其中一份。

速食、咖哩、拉麵、烏龍麵、早餐店、早午餐、牛肉麵、牛排、小吃店、快餐便當、咖啡廳、輕食咖啡廳、韓式、鍋物、素食、冰店、甜點、粥店、港式、台式、飯糰飯捲、鵝肉專賣、燒臘、義式、壽司、泰式、日式定食。

- **固定的是分類名稱、順序及可選範圍**；試算表 **RestaurantsFree → G 欄 category** 決定每間店歸哪一類及各類店家數量。
- 「不限」第一個；其他依上述順序，沒有店家的類別不顯示；「尚未分類」有店家時放最後。
- 同店多類別以頓號分隔，例如 `早午餐、輕食咖啡廳`；不會重複列入轉盤。
- 舊值「韓式料理」讀取時統一為「韓式」，不覆寫原儲存格。其他名稱不猜測、不合併。
- 主清單外的名稱或錯字不會產生新卡片。只有無效分類的店保留於「不限／尚未分類」，並提示餐點類別待確認；混合分類保留有效部分。原試算表不會被改寫。
- 團長新增店家時只可勾選這 27 類，傳入清單外名稱也不能存入。分類未確認仍可先留空。
- 修改店家在這 27 類之間的歸類，只需重新整理店家；**要新增第 28 個類別，需修改主清單並重新部署兩份檔案**。
- 網站不讀試算表下拉選單的選項設定。請讓下拉選單與上述 27 類一致，再將分類填到店家列。
- G 欄空白、其他或 unknown 時，才沿用「原始清單」中同店家 ID 的有效分類；不依店名猜測。
- 「素食」分類與 M 欄 diet 分開，葷素請確認後填寫，不能只靠分類推定。

更新到 **6.8.0** 後，在「店家名單 → 重新整理店家」讀取你已填好的內容。

## 食友怎麼投稿？

「選餐點」、「挑店家」與「店家名單」都有 **找不到你喜歡的店家？ → 我要推薦店家**。

- 必填：店名、Google Maps 分享連結。
- 選填：推薦理由，最多 1000 字。
- 不用填經緯度、電話或營業時間。
- 可先填表，送出前才要求 Google 登入；登入後內容保留，要再按一次送出。不會自動投稿。
- 只接受 Google Maps 連結，不抓取或解析 Google 店家資料；不使用付費 API。
- 投稿不會直接加入候選名單或轉盤，須由團長確認。投稿內容及帳號只供團長查看。
- 同次送出重試不重複新增；相同店名與連結已有待確認投稿時會提醒。每個帳號 10 分鐘最多 3 間、滾動 24 小時最多 10 間。

## 團長怎麼處理？

1. 網站按 **團長登入**，輸入原本通關密語。
2. 按 **查看店家投稿**。可看店名、推薦理由、Google Maps 連結與投稿帳號。
3. 確認店家後，使用原本新增店家的方式加入名單；店家位置與營業資訊仍由團長確認。
4. 完成確認或決定不加入後，可按 **標記已處理** 收起投稿。

「標記已處理」不會自動新增店家，也不刪除投稿。這可避免未確認的推薦直接進入抽選。查看與處理每次都驗證團長權限；Google 一般會員不能讀取投稿清單。關閉視窗或團長登出後清除私人投稿內容，遲到的回應不顯示。

### 新增 Suggestions 分頁

第一次投稿或團長開啟投稿清單時，程式會自動建立 **Suggestions**：

`id | request_id | name | maps_url | note | submitter_key | submitter_email | created_at | status | reviewed_at`

- `status`：`pending` 待確認、`done` 已處理。
- `submitter_email`：由 Google 登入取得，不信任使用者自行提供的帳號。
- 原本店家、評論、會員及投票分頁不需要重新匯入或改表頭。
- 試算表仍保持限制共用。

## 用字調整

已檢查入口、挑店家、店家名單、轉盤結果、帳號、團長登入、出發點、資訊提醒及新增店家表單：

| 舊說法 | 新說法／操作 |
|---|---|
| 管理員／名單管理者 | 團長 |
| 預算未標記／葷素未標記 | 預算還沒確認／葷素還沒確認 |
| 基本資料待確認，暫不開放抽選與評論 | 店名或位置還沒確認，暫時不能抽選或留言 |
| 一般使用者看到試算表表頭、編號與匯入說明 | 改成請團長確認及重新整理店家的操作提示 |
| 直接要求填寫出發點經緯度 | 先用定位／地圖選點；手填位置收進可展開的進階選項 |
| HTTPS Google Maps 格式錯誤 | 引導到店家頁按「分享」再複製連結 |

管理者維護資料必須知道的欄位名稱保留在文件，沒有混進一般選店流程。出發點進階欄位及團長新增店家的位置欄位仍保留緯度／經度的正確名稱。

## 更新與驗收

1. 下載新版 ZIP，完整替換 **Code.gs、Index.html**。
2. 原部署「編輯 → 新版本 → 部署」。執行身分保持「我」、存取保持「任何人」；Google 登入與管理密語不用重設。
3. 「使用說明」確認版本 **6.8.0**。
4. 核對實際分類及台式店家數，再測試投稿與團長處理。

本機測試包含動態分類、權限、輸入檢查、重試去重、投稿頻率、投稿分頁、原店家名單不被修改、匿名食評回歸及手機尺寸。Google／試算表連線以測試替身驗證；正式部署與 iPhone Safari 仍需上線後實際確認。
