# v6.8：店家完整頁、送出確認與載入提示

- 「店家與食評」改名為 **店家名單**。
- 點店家會進入網站內的完整店家頁。桌機左側店家資訊、右側評論；手機上下排列。使用「返回店家名單／返回剛才的畫面」回到原位置，保留搜尋、分類及抽選勾選。
- 推薦店家的區塊移到選餐點、挑店家及店家名單的底部。
- 移除入口「一間店可以有多種類別，選不限就能一起挑」獨立提示框。
- 新增 **全選目前顯示**，依當下分類、篩選與搜尋選店。這會替換本次勾選，超過 20 間時需縮小名單才能確認抽選；也可按「只選目前前 20 間」。轉盤仍為 2～20 間。
- 評論維持只能新增，沒有修改或刪除。按送出後，先核對匿名／暱稱、品項、回饋、分數，確認才送出；返回修改或關閉確認視窗會保留草稿。
- 首次讀名單、重新整理店家、評論、投稿、登入確認、天氣及地圖等資料載入使用共用旋轉提示；失敗、逾時或完成後結束。若同時有多項工作，會等最後一項完成再隱藏。減少動態效果設定下使用靜態提示。

評論與投稿仍需 Google 登入，瀏覽和抽選不用。團長新增店家的填寫視窗保留；店家資訊與閱讀評論改為完整頁面。

## 為什麼顯示「Google 登入尚未準備好」？

這個提示來自網站的設定檢查，不是 Google 拒絕了某個帳號。舊版首次讀名單時取得登入設定狀態，以下任一項空白或格式不符，就會停用登入按鈕：

| Apps Script 指令碼屬性 | 要填的內容 |
|---|---|
| `GOOGLE_CLIENT_ID` | Google 的網頁應用程式用戶端 ID，結尾為 `.apps.googleusercontent.com` |
| `GOOGLE_CLIENT_SECRET` | 該用戶端的密鑰；只填入指令碼屬性 |
| `GOOGLE_REDIRECT_URI` | 現在使用的 Apps Script 正式網址，結尾 `/exec` |

部署選「任何人」只開放瀏覽，並不會自動建立或填入上述設定。

### 已有 Google 登入用戶端

1. 開啟 Apps Script **專案設定 → 指令碼屬性**，核對上述三個名稱及內容，避免前後空白。
2. Google Cloud 的該用戶端也要設定相同的「已授權的重新導向 URI」，與目前 `/exec` 完全一致。
3. 儲存後回網站，按 **Google 登入 → 重新確認登入是否可用**。新版不需要重開整個網站才能取得新的設定狀態。
4. 若仍不可用，先 **團長登入**，再到 **Google 登入 → 檢查 Google 登入設定（團長）**，查看哪項尚未填寫或格式需要確認。

檢查只顯示設定名稱與狀態，不顯示密鑰或設定值。一般訪客無權取得完整檢查結果；離開視窗或團長登出後會清除結果。全部顯示已填寫只表示格式通過，不代表 Google 已驗證用戶端或網址。

### 還沒有 Google 登入用戶端

依 [Google 登入設定指南 B、C 節](google-login.md#b-建立-google-登入用戶端) 建立網頁應用程式用戶端，將 ID、密鑰及重新導向網址填入 Apps Script。只需基本身分資訊，不要把 Google Maps 金鑰填到這裡。

Google 用戶端建立及重新導向網址規則見 [Google 官方說明](https://developers.google.com/identity/protocols/oauth2/web-server#creatingcred)。不要將密鑰貼到聊天、試算表或 GitHub。

1. 下載最新 `Lunch-Club-Apps-Script.zip`，完整替換 **Code.gs、Index.html**。
2. **管理部署 → 編輯 → 新版本 → 部署**。執行身分保持「我」、誰可以存取保持「任何人」。
3. 使用說明確認 **6.8.0**。
4. 試算表、27 類主清單與既有店家／評論不用重建；`appsscript.json` 不變。

Google 登入設定屬於你的私人專案，程式更新不會自動替你建立 Google 用戶端、修改其設定或填入密鑰。
