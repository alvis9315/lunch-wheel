# v6.4：用餐點挑午餐，獨立瀏覽食評

頂端可獨立切換「抽午餐／店家與食評」。食評區不套用午餐篩選或更動勾選，搜尋、閱讀心得不需先完成三步驟；評論與投票沿用 Google 登入。v6.4 入口改為具體餐點，同店可以有多種類別。分類如何填入試算表見 [補資料指南](fill-restaurant-data.md)。

## 更新已上線的網站

1. 下載最新版 `Lunch-Club-Apps-Script.zip` 並解壓。
2. 用其中的 **Code.gs 全文**取代 Apps Script 的程式碼；用 **Index.html 全文**取代 HTML 檔 `Index`。
3. 儲存後，選「部署 → 管理部署 → 編輯 → 新版本 → 部署」。保持原部署網址、試算表及指令碼屬性。這次沒有新增權限，`appsscript.json` 不需更動。
4. 重新開啟 `/exec`；使用說明應顯示 **版本 6.5.0**。

只更新 GitHub 不會更新已部署的網站。請複製 ZIP 或 `dist/Code.gs` 的完整內容；不要單獨使用 `apps-script/Code.gs`。

## 使用流程

1. **選餐點**：開啟網站會讀取現有名單。「不限」固定第一個，包含所有店家；入口顯示早餐／早午餐、牛肉麵、牛排等餐點類別與店數。0 間的類別標示尚無分類資料並停用，補好資料後即可選。同店可出現在不同類別，總名單與轉盤中只列一次。讀取中有動畫，可以取消，失敗或逾時可重試。
2. **篩選、挑店家**：左側設定距離、天氣、葷素、預算與營業時段；右側同步顯示符合條件的卡片。桌機每排 3 張，平板 2 張，手機 1 張，手機篩選可以展開／收起。勾選 2～20 間，按右上方「確認名單，去抽午餐」。
3. **轉盤**：獨立頁面只放轉盤及返回調整名單的按鈕。確認時不符合條件的勾選會略過；抽選前再次讀取資料核對。正常動畫約 2.5 秒；開啟減少動態效果時縮短動畫。每間店抽中機會相同。

重新選餐點會清空本次勾選並重設條件；返回挑店家會保留勾選與條件，但需重新確認。搜尋店名只影響顯示，不取消已勾選的其他店；畫面會顯示目前勾選數。超過 20 間的清單可明確按「勾選目前前 20 間」，不會自動替使用者挑前 20 間。

「自己建立」入口及操作已停用，先前保存在裝置的私人名單不會被改寫或刪除。Google Maps 搜尋加入的重做另行討論。

## 分類從哪裡來

分類先讀 `RestaurantsFree` 的 **category（G 欄）**。同格可填多個餐點，以頓號分隔。葷素是另一個條件，請填 **diet**，不要把素食混成唯一餐點類別。

支援：早餐／早午餐、便當、牛肉麵、拉麵、其他麵食、牛排、火鍋、咖哩、義大利麵、小吃、輕食、咖啡／甜點、冰品。新分類不會依店名或店型自動推測有哪些餐點；管理員新增店家時可以直接勾選多類。

### 舊匯入名單的銜接

若 category 是空白、unknown 或「其他」，且同一份試算表保留 **原始清單** 分頁：

- 依「系統店家 ID」對應「店家類型」欄，不依店名或列順序猜測。
- 只做可確定的名稱對應：例如早餐店 → 早餐／早午餐、咖啡廳或甜點 → 咖啡／甜點、冰店 → 冰品。咖啡廳不自動加入其他餐點類別。
- 正餐、台式、日式、韓式、西式、麵食、便當／快餐等舊大類保留資料但暫列尚未分類，等管理者確認具體餐點。
- 不覆寫任何儲存格，不修改店家 ID，不影響評論關聯。
- 已填寫的具體 category 優先；來源 ID 重複、分類不支援或表頭不符時不採用來源分類。
- 沒有原始分頁時仍可使用。未分類店家列在「尚未分類」，也包含在「不限」內。

**正餐不等於拉麵或牛排。** 只有原始正餐資料時，網站不會憑店名補造細分類。升級到新版後，管理者在 `RestaurantsFree.category` 填入確認的餐點即可；改分類不需再次部署。請勿整張重新匯入而覆蓋已累積的店家、評論、投票與會員資料。

## 防呆與驗證範圍

- 必要資料不全的店仍保留在店家地圖名單，暫不提供抽選；類型店數是完整清單數，篩選後的可抽店數會另外顯示。
- 缺預算、葷素、避雨或營業時間，不會當作符合指定條件；不限時不以這些選填缺值排除。
- 不足 2 間、超過 20 間、用餐結束早於開始、讀取中，都不能確認抽選。
- 測試包含來源分類、2～20 間限制、篩選、確認後名單、動畫、取消與逾時、地圖失敗、私人資料保留。
- 瀏覽器驗證寬度：375、390、430、768、1024、1440。測試使用本機試算表替身；線上資料與 iPhone Safari 仍需部署後實機確認。
