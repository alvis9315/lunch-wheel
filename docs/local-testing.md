# 先在本機測試，再部署

## 開啟方式

在專案資料夾開 PowerShell，執行：

```powershell
npm run dev
```

看到啟動訊息後，用瀏覽器開啟 **http://127.0.0.1:5173/**。Windows 也可雙擊專案內的 `start-local.cmd`。需要 Node.js 18 以上，這個測試服務不需要安裝其他套件，也不需要 Google 金鑰。

按 Ctrl+C 或關閉命令視窗即可停止。若 5173 已被其他程式使用，可先執行 `$env:LUNCH_DEV_PORT = '5174'`，再啟動並使用畫面提示的新網址。

## 可以試什麼？

- 30 間虛構範例店家，涵蓋所有餐點類型、多類別、葷素、預算、距離、公休和資料缺漏。
- 類型、篩選、勾選 2～20 間、轉盤動畫、結果、店家完整頁及手機排版。
- 點登入後選 **測試食友 A／B**，不會要求真實 Google 帳密。可測匿名、暱稱、確認關窗、評論草稿、送出確認，以及按讚／按爛／取消。
- 團長測試密語為 `lunch-local-admin-only-12345`，只適用本機範例。可測管理者查看留言帳號、新增店家及處理投稿。
- 留言與投票會寫入測試服務的記憶體。重新整理頁面仍保留，停止服務後清除；頁首「測試說明 → 恢復範例資料」可隨時重來。

修改 `src/` 或 `apps-script/` 後，重新整理瀏覽器就會重新建置並載入，範例資料及已寫入內容會保留。沒有自動強制刷新，以免打斷正在填寫的評論。修改測試服務本身時，需重新啟動 `npm run dev`。

## 本機與線上的差異

| 項目 | 本機 | Apps Script 最後驗收 |
|---|---|---|
| 頁面與操作流程 | 使用相同的前端程式 | 確認 Google 網頁容器沒有額外影響 |
| 留言、投票、資料檢查 | 執行相同的 Code.gs，模擬試算表儲存 | 確認真實試算表權限與欄位 |
| 登入 | 測試帳號，模擬 Google 回應 | 確認真實 OAuth 設定、回呼與授權 |
| 地圖、天氣、字型 | 仍由原本的免費來源載入，需要網路 | 使用相同來源 |

**本機通過不代表 Google 授權與線上寫入已驗證。**之後先在這裡修好畫面和流程，準備好一批修改後，再更新 Apps Script 做一次整合驗收。

測試服務只開放這台電腦（127.0.0.1），不是公開網址，也不能直接在另一台 iPhone 開啟。可先用瀏覽器裝置模擬檢查各種手機寬度，真正 iPhone Safari 的最後驗收使用部署網址。

## 自動測試

```powershell
npm test
```

涵蓋資料檢查、分類、登入驗證、評論隱私、重複送出、投票、投稿，以及本機測試服務的操作。測試資料全部是虛構內容。

本機工具位於 `scripts/local-*`，不會被包進 `dist/Index.html` 或 Apps Script 部署檔。正式網站不會有測試帳號或本機測試密語。
